## Protocol model

- **STP** prevents Layer-2 loops by electing a loop-free topology and blocking redundant paths.
- **RSTP** provides the same core loop-prevention function with faster convergence and is recommended by current TP-Link/Omada standalone and Controller guidance for typical deployments.
- **MSTP** extends the model by mapping VLANs into MST instances so different VLAN groups can use different loop-free paths.

Do not infer that every Omada/JetStream switch supports every mode. Exact model, hardware revision, firmware, management mode and Controller version remain execution-time gates.

## 2026 CLI normalization

The May 2026 **Managed Switches CLI Reference Guide REV2.0.0**, Chapter 37, publishes:

```text
spanning-tree
no spanning-tree

spanning-tree mode { stp | rstp | mstp }
no spanning-tree mode

spanning-tree priority <priority>
no spanning-tree priority
```

It separately requires enabling spanning tree on participating interfaces:

```text
interface <exact-interface>
spanning-tree
```

The current CLI reference publishes the mode default as `stp`; bridge priority is `0..61440` in multiples of 4096 with default `32768`, and a **lower numeric value means higher priority**.

Port/CIST parameters are represented separately:

```text
spanning-tree common-config   [ port-priority <priority> ]   [ ext-cost <cost> ]   [ int-cost <cost> ]   [ portfast { enable | disable } ]   [ point-to-point { auto | open | close } ]
```

The cited defaults include port priority `128`, path cost `0 = auto`, Edge/Portfast disabled, and point-to-point `auto`.

### Timers

```text
spanning-tree timer [ forward-time <s> ] [ hello-time <s> ] [ max-age <s> ]
spanning-tree hold-count <value>
spanning-tree max-hops <value>
```

The current CLI reference publishes source-scoped defaults of Forward Delay `15s`, Hello Time `2s`, Max Age `20s`, Hold Count `5`, and Max Hops `20`. These are not promoted into an exact-device invariant without applicability evidence.

### Protection controls

The 2026 CLI reference includes:

```text
spanning-tree bpdufilter
spanning-tree bpduflood
spanning-tree bpduguard
spanning-tree guard loop
spanning-tree guard root
spanning-tree guard tc
```

`bpduguard` is documented for **edge ports**. If such a port receives a BPDU, the cited guide places it in `ERROR-PORT`; recovery requires explicit intervention. Protection commands must therefore never be generated by a generic “make this safe” shortcut.

### MST region and instances

```text
spanning-tree mst configuration
  name <region-name>
  revision <revision>
  instance <instance-id> vlan <vlan-list>

spanning-tree mst instance <instance-id> priority <priority>
```

Per-instance port priority/cost is configured independently. Treat the region identity as the tuple:

**Region Name + Revision + VLAN-to-instance mapping**

All intended members of one MST region must match that identity. Current Controller guidance states that VLANs not explicitly mapped to an instance are mapped to **CIST** in that workflow.

## Read-back is the PASS gate

Canonical CLI evidence surfaces include:

```text
show spanning-tree active
show spanning-tree bridge
show spanning-tree interface [<exact-interface>]
show spanning-tree interface-security [<exact-interface>]
show spanning-tree mst configuration [digest]
show spanning-tree mst instance <instance-id> [interface [<exact-interface>]]
show spanning-tree instance
```

The cited `show` commands are documented without a privilege requirement and are available from Privileged EXEC / configuration modes where specified.

PASS requires **operational topology evidence**, not command acceptance:

1. global mode/bridge parameters match intent;
2. every affected port has the expected role/state/status and cost/priority/edge/protection state;
3. every MST region/instance/mapping/port is verified where MSTP is used;
4. the expected links are Blocking/Forwarding after convergence;
5. management/controller reachability remains healthy.

## Standalone GUI

Current 2026 standalone STP/RSTP guidance explicitly says to configure STP/RSTP **before connecting redundant links** to avoid a broadcast storm. It uses global enable/mode plus port-level enable, and `STP Summary` for operational read-back.

Current MSTP guidance similarly configures all switches before closing the loop, then defines a consistent region and maps VLAN groups to instances. The official example maps VLAN 101–103 to instance 1 and VLAN 104–106 to instance 2, then deliberately adjusts instance priorities and path costs to produce separate forwarding paths.

## Controller mode

Current Controller guidance for **V6.2.10+** documents STP/RSTP and MSTP for the listed Omada Campus/Aggregation/Access families. Global configuration and participating-port configuration remain separate.

Important conflict:

> Loopback Detection and Spanning Tree may be enabled on the same device, but **not on the same port simultaneously** in the cited current Controller workflow.

Current Controller operational states include `Blocking`, `Learning`, `Forwarding`, and `Disconnected`. Controller V6.1+ can also display converged spanning-tree topology and blocked links in Dashboard > Topology for supported switch classes.

### Version-scoped MSTP conflict

An older official **Controller v4 & v5** guide states that MSTP was not supported in Controller mode. Current **V6.2.10+** guidance explicitly supports MSTP.

This is retained as a **version-scoped behavior change**, not “one source is wrong”. Automation must resolve Controller version before selecting a workflow.

## Safety contract

1. Resolve exact device/firmware/management mode/Controller version and port identity.
2. Discover current global STP mode, timers/priorities and all affected port roles/states.
3. For MSTP, snapshot region name, revision, complete VLAN-instance mapping, instance priorities and per-instance port values.
4. Identify active management/control-plane paths.
5. Do not mark a port Edge/Portfast unless it is positively known to be an end-device edge.
6. Detect Controller same-port STP/Loopback-Detection conflicts.
7. If a physical redundant path is not already closed, keep it open until spanning tree is configured and verified.
8. Obtain production-write approval before topology-affecting changes.
9. Apply only the intended delta and wait for convergence.
10. Read back every affected switch/port/instance and verify management reachability.
11. Persist standalone CLI state through the **4.02 save contract** only after operational verification.

A command/UI action accepted without converged topology evidence is `EXECUTED_UNVERIFIED`, not PASS.

## Rollback

Rollback restores the **exact observed pre-change** global mode, priorities, timers, port enable/cost/priority/edge/P2P/protection flags, MST region identity, mappings and per-instance values. “Disable STP” is not a safe generic rollback because it can reintroduce a Layer-2 loop.

LAG/LACP construction remains **4.10**. RPVST remains outside 4.09 except as an exact-capability boundary.
