## Current official evidence

- `How to Configure ACL on Omada AP via Omada Controller`, current 2026 surface: https://support.omadanetworks.com/de/document/13284/
- Current Controller document index also lists this AP ACL guide dated 2026-08-24.
- Historical/currently served Guest SSID access-control guidance documents SSID Isolation as a distinct same-SSID/same-AP client-isolation control: https://support.omadanetworks.com/se/document/12928/

The AP ACL guide exposes policy, protocol, source and destination selectors for wireless traffic restriction. ACL-based wireless policy and SSID/client isolation are related security controls but are not the same state plane.

## State planes

- EAP ACL object enable state
- ordered/defined policy rules
- source SSID/client/network selector
- destination IP/group/network selector
- protocol/action
- SSID/client-isolation toggle where supported
- VLAN/routing dependency
- verification traffic matrix

## Boundaries

- AP ACL support and field set are Controller/version/device scoped.
- Same-SSID client isolation cannot be inferred from a deny ACL unless the exact traffic path/rule semantics prove it.
- SSID VLAN isolation is not equivalent to client isolation: routed inter-VLAN traffic may still be possible when Layer-3 routing exists.
- Switch Port Isolation is a different feature and remains outside this AP/WLAN work unit.

## Verification target

PASS requires exact policy read-back plus representative traffic tests between wireless clients and protected resources. Test same-SSID peers separately from cross-SSID/VLAN flows. Verify DHCP/DNS/gateway access remains available when intended.
