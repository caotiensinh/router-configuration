# Agent 08 — 14.3 Configuration Report Schema Draft

Status: DESIGN_DRAFT_DEPENDENCY_BLOCKED
Observed: 2026-09-15

## Goal

Define a deterministic configuration-report artifact generated from the actual approved/executed changeset and verification evidence, not from free-form AI narrative.

## Required sections

1. **Identity / scope**
   - project/run ID
   - site/device exact identifiers
   - hardware revision / region / firmware / Controller version
   - report generation timestamp

2. **Intent**
   - normalized user intent
   - resolved assumptions
   - unresolved/blocked items

3. **Pre-change state**
   - snapshot references and hashes
   - backup references
   - management/recovery path

4. **Approved changeset**
   - changeset hash
   - ordered operations
   - per-operation risk class
   - per-operation official-source provenance

5. **Execution evidence**
   - actual operation result
   - read-back/verification evidence
   - partial/failed operations
   - stop-on-failure events

6. **Rollback evidence**
   - whether rollback was required
   - exact rollback operations
   - post-rollback verification

7. **Desired vs actual final state**
   - VERIFIED / EXECUTED_UNVERIFIED / BLOCKED / NOT_APPLICABLE / UNKNOWN
   - deviations with reason and evidence

8. **Security / compliance observations**
   - only mappings backed by the technical baseline; no generic certification claim

9. **Artifact manifest**
   - source hashes
   - generated artifact hashes
   - software/KB/compiler versions

## Integrity rules

- Never report a planned operation as executed.
- Never report command acceptance as verified state.
- Never hide partial execution.
- Never promote virtual/protocol evidence to hardware-verified evidence.
- Any missing mandatory evidence must remain explicit.

## Dependency gate

Cannot be marked PASS until the Phase 13 transaction engine emits durable snapshot, diff, execution, verification, rollback and final-validation records.
