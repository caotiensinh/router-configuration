## Normalized boundaries

- Open API supports programmatic integration with Controller services; exact endpoint coverage is version-scoped and must not be invented.
- Application registration and authorization mode are separate from individual API operations.
- Current V6 guide documents OAuth-based authorization with authorization-code mode and client mode.
- Access tokens are temporary credentials; refresh/reissue behavior depends on authorization mode.
- One-Access-Token account-level access to multiple local controllers is a distinct 2026 workflow and must be gated by exact deployment capability.
- External Portal API is a specialized API surface and must not be generalized to all Controller configuration APIs.

## Security gates

Client key/secret, access tokens and account-level API keys are secrets and must never be persisted into normal evidence artifacts or logs. Scope/permissions, token lifetime, Controller version, deployment type and API endpoint provenance are mandatory before execution.

## Verification target

PASS requires authorization success plus read-back of the exact created/changed object and explicit API response validation. HTTP success alone is not proof of desired Controller state.
