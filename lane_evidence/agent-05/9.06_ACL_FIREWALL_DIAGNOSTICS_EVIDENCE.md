The current Fusion troubleshooting guide provides a minimum ACL check sequence: verify the rule is enabled; verify protocol, policy, source, destination and ports; verify rule ordering; and verify Time Range and States Type in Advanced Settings. It also tells operators to check Port Isolation and MAC filtering when clients in the same VLAN cannot communicate.

## RCA graph planes

- policy object exists/enabled
- rule order / first-match position
- source selector correctness
- destination selector correctness
- protocol/port/application match
- permit/deny action
- time-range active state
- stateful/states-type behavior
- routing/VLAN reachability prerequisites
- NAT/PBR interaction
- port/client isolation and MAC filtering interaction
- actual flow/counter evidence

## Minimum-check strategy

1. Reproduce the exact failing flow tuple and direction.
2. Verify L2/L3 reachability before attributing the failure to ACL.
3. Read the active ordered ACL set.
4. Identify the first rule that should match the flow.
5. Validate source/destination/protocol/ports/action/time/state fields.
6. Check whether another isolation/MAC-filtering/NAT/PBR policy changes the path.
7. Compare a known-permitted flow and a known-denied flow.
8. Use packet capture/counters where available to locate the actual drop point.

## Diagnostic outcomes

- `RULE_ORDER_SHADOWING`

- `STATE_TYPE_MISMATCH`

- `EXECUTED_UNVERIFIED`
- `UNKNOWN`

## Safety

Troubleshooting must not "fix" the issue by globally disabling firewall/ACL. Any diagnostic mutation requires exact snapshot and rollback. Management/Controller traffic must remain protected.
