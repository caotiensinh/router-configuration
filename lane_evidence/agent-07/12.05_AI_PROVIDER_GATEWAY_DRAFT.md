# Agent 07 — 12.5 AI Provider Gateway Contract Draft

Status: DESIGN_DRAFT_DEPENDENCY_BLOCKED
Observed: 2026-09-15

## Goal

Provide one provider-neutral interface for OpenAI, Claude and local-model backends while ensuring that AI output can never directly authorize vendor commands.

## Proposed contract

`AIProvider` must expose a narrow normalized surface:

- `analyze_intent(context) -> ProposedIntent`
- `identify_missing_inputs(context) -> MissingInput[]`
- `propose_vendor_neutral_ir(context) -> NetworkEngineeringIRCandidate`
- `explain_plan(plan) -> HumanReadableExplanation`

Provider output is **advisory only**. It must never emit an executable command object accepted directly by the transaction engine.

## Mandatory trust boundary

Every provider result enters the same deterministic validation pipeline:

1. parse provider response into a vendor-neutral candidate;
2. reject unknown/unmodeled fields;
3. resolve against VERIFIED ACTIVE KB only;
4. compile only through the deterministic vendor compiler from Phase 8;
5. require per-operation provenance and exact applicability evidence;
6. reject any command/action lacking verified source mapping;
7. hash the approved changeset before execution.

This enforces canonical task 12.6: **all unverified AI-generated commands are rejected**.

## Provider isolation

- No provider-specific prompt/output format may leak into compiler semantics.
- Secrets/API keys stay in provider configuration, never KB artifacts/logs.
- Local models have identical authorization limits to hosted providers.
- Model confidence is not vendor evidence.
- Provider disagreement is surfaced as analysis conflict, not resolved by majority vote.

## Dependency gate

This draft cannot be marked PASS until Phases 8.1–8.10 (schema/compiler/provenance) and 12.1–12.4 (IR, missing-input resolver, auto-discovery, contradiction detection) are durable.

## Next lane step
